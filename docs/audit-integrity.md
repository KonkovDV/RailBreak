# Аудит целостности ядра, 

Внешняя проверка ядра `libtram_dr` в режиме «жюри + red team» на коммите
`a3a5623`. Правки касаются только контрактов целостности и численной части;
модель кузова, наблюдаемость и пороги статусов не переписывались.

Вывод, который важен для защиты: **фильтр действительно fail-closed по обрыву
данных, но не был fail-closed по «правдоподобным» данным** — по молчанию
пакетов, по нулевым энкодерам на скорости и по нефинитному шагу времени.
Это класс ошибок, при котором статус остаётся `OK`, а путь уже неверен, то
есть ровно то, что метрика HMI-rate обещает исключить.

## Как воспроизвести

```bash
cmake -S standalone -B standalone/build -DCMAKE_BUILD_TYPE=Release
cmake --build standalone/build --parallel
ctest --test-dir standalone/build --output-on-failure
```

`standalone/test_integrity_contracts.cpp` — 63 проверки. На ядре `a3a5623`
не проходят 42 (шесть классов дефектов, не 42 независимые ошибки),
на ядре этой ветки — 0. Проверки намеренно без `assert()`: они обязаны
работать и под `NDEBUG`.

### Одна унаследованная проверка требует замены

`standalone/test_core.cpp` в этой ветке не изменён, и его случай
`zupt off stop` теперь падает — намеренно. Фикстура разгоняет вагон
(`notch = 0.8`, 800 кадров, s > 50 м), затем отпускает тягу и тормоз и
подаёт 40 кадров нулевых энкодеров, требуя `kStandstill`. Это ровно
сценарий заклиненных осей на выбеге, то есть проверка закрепляла опасное
поведение, а не защищала от него. Смысл случая (привязка стоянки к массовой
двери) сохраняется, если довести вагон до остановки физически:

```c++
    u.notch = 0.0;
    u.brake = 0.5;
    double v_body = e.x.v_mps;
    while (v_body > 0.0) {
      v_body = std::max(0.0, v_body - 1.2 * 0.02);
      const double w = v_body / r;
      double omega[4] = {w, w, w, w};
      e = ukf.predict_and_update(u, omega, 4, 0.02);
    }
    for (int k = 0; k < 40; ++k) {
      double z[4] = {0.0, 0.0, 0.0, 0.0};
      e = ukf.predict_and_update(u, z, 4, 0.02);
    }
    expect(e.mode == tram_dr::Mode::kStandstill, "zupt off stop");
```

С этой заменой локально проходят оба набора: `test_core` и
`test_integrity_contracts`. Утверждения про массовую дверь
(`!e.zupt_at_stop`, `e.p_mm < p_hold + 0.5*door`) ослаблять нельзя.

## Дефекты и что изменилось

### 1. Свежесть данных подменялась счётчиком выборок (P0)

`classify` старила колёсный канал по условию `n > 0 && n_omega_used_ == 0`.
При `n == 0` (кадра нет, `nullptr`, предикт-онли) возраст не рос вообще, а
`n_omega_used_` оставался прежним. Итог: после нормального движения топик мог
молчать сколько угодно — статус оставался `OK`, `n_omega_used` показывал старое
число осей, NIS оставался «валидным» от прошлого кадра.

Симметричная ошибка в обратную сторону: настоящая стоянка (нулевые, но живые
энкодеры) проходила через `zupt_gate` и не вызывала `update_wheels`, поэтому
счётчик оставался нулевым и стоянка выглядела как обрыв энкодеров → `LOST`.

Теперь возраст считает **время без пригодных измерений**: `n_omega_used_` и
`nis_valid_` обнуляются в начале каждого шага, ZUPT считается свежим
свидетельством (обновляет SCA, счётчик осей и снимает флаг обрыва),
а `nullptr` с ненулевым `n` больше не может обновить возраст.

### 2. Отпущенный тормоз считался доказательством стоянки (P0)

```c++
return wmax < 0.08 && std::fabs(u.notch) < 0.05
       && (u.brake < 0.15 || vabs < 0.35);
```

Ветка `u.brake < 0.15` означает: на выбеге, когда все энкодеры одновременно
отдают нули (заклиненные оси, юз, обрыв шины), фильтр через 0.3 с объявляет
стоянку и обнуляет скорость движущегося вагона. Проверка «нет ZUPT на
блокировке» в `test_core.cpp` это не ловила, потому что там тормоз зажат
(`brake = 0.85`) — то есть тест проверял единственную ветку, в которой
дефекта нет.

Измеренный эффект: после разгона до 5 м/с и 16 кадров нулей исходное ядро
даёт `v = 0` и режим `standstill`; исправленное — `v ≈ 4.66` м/с и не
стоянку.

Теперь стоянка требует свежих валидных нулей по **всем** каналам пакета,
доступной ручки и собственной оценки `|v| < 0.35` м/с. Частично нефинитный
пакет стоянку не доказывает. Отсутствие кадров (`n == 0`) больше не
продлевает удержание, а выход из ZUPT сбрасывает и режим (раньше
`mode == kStandstill` залипал после отъезда, потому что `classify`
возвращался раньше сброса).

### 3. Канальные статусы противоречили агрегату (P1)

`confidence_v` учитывал только расхождение осей и `P_vv > 4`. Поэтому
`confidence_v = OK` был возможен при активном общемодовом скольжении, при
некалиброванном радиусе и при устаревших колёсах. `confidence_s` не учитывал
свой же `PL_s >= AL_s`, а агрегат мог быть `DEGRADED` при обоих канальных
`OK` — а публикуется как раз худший из каналов.

Теперь: общемодовое скольжение, неизвестный `r0`, устаревшие колёса и
отсутствие ручки понижают **скорость**; превышение `PL_s` над `AL_s` и
расхождение осей понижают **путь**. Латч по `s` после юза сохранён:
`confidence_v` возвращается в `OK`, `confidence_s` — нет.

Важно для формулировок: неизвестный `r0` — это общий масштаб, он портит
не только путь, но и скорость. Прежний текст «`r0_uncalibrated` → DEGRADED
по `s`» занижал последствие.

### 4. Нефинитные вход и шаг времени попадали в состояние (P0)

`dt_s` и управление не проверялись, а `last_u_`/`last_dt_s_` перезаписывались
до любых проверок. `dt = NaN` или `notch = NaN` уносили в `NaN` оценку,
ковариацию и все производные диагностики; `dt <= 0` и гигантский шаг
принимались молча.

Теперь действует контракт: конечные управления и `0 < dt <= 0.20` с. Кадр с
нарушением отклоняется **покадрово**: последняя конечная оценка сохраняется,
на выход идёт `LOST` и `sensor_fault`, состояние не продвигается. Постоянный
латч до `reset()` намеренно не делался — один битый пакет DDS не должен
навсегда выключать резервный контур; после возврата корректных входов
оценщик восстанавливается (это тоже закреплено тестом).

Дополнительно шаг стал атомарным: если результат оказался нефинитным или
ковариация перестала быть разложимой, состояние откатывается к предыдущему,
`chol_fail` инкрементируется и кадр отклоняется. Раньше отказы `chol` внутри
`predict`/`update` молча выходили без инкремента счётчика.

### 5. `chol` принимал NaN как успех, `project_pd` портил корректную матрицу (P1)

`chol` проверял только `s <= 0`. Для NaN это сравнение ложно, поэтому
разложение «удавалось» и возвращало NaN-фактор; размерность и указатели не
проверялись при фиксированном буфере `16×16`.

`project_pd` выполнял 24 **вращения** Якоби (переменная называлась `sweep`),
хотя для `L = 12` в одном полном проходе 66 внедиагональных пар. После этого
остаточные внедиагональные элементы отбрасывались и матрица собиралась из
одной диагонали. Для уже корректной плотной SPD-матрицы это давало
максимальное отклонение `0.1097` — то есть проекция сама уничтожала
корреляции состояния на каждом шаге.

Теперь: `chol` отвергает нефинитные входы и некорректные размерности;
`project_pd` сначала проверяет, не является ли матрица уже SPD с запасом
по порогу (тогда она не трогается вовсе — измеренное отклонение `0`),
а при ремонте крутит Якоби до сходимости с бюджетом `32·n²` вращений и,
если бюджет исчерпан, добавляет консервативную оценку Гершгорина вместо
молчаливого отбрасывания остатка.

### 6. Конфигурация не валидировалась (P2)

`set_params` / `set_plant` / `set_sca` принимали любые числа: нулевой радиус,
отрицательные шумы и таймауты, `α`, при котором масштабированное UT
неопределено. Отдельно: `ScaParams::r0_m` мог не совпадать с `PlantParams::r0_m`,
и тогда консенсус осей и модель измерения работали в разных масштабах.

Теперь параметры проверяются на конечность и физический смысл, `set_plant`
синхронизирует радиус в SCA, а рассогласование радиусов отвергается.
Следствие для эксплуатации: узел с некорректным YAML падает на старте,
а не публикует «правдоподобную» оценку.

## Что не проверено и не заявляется

- Санитайзеры (ASan/UBSan) в моей песочнице не запускались: в образе нет
  `libasan`. Прогон в CI обязателен, задание `asan` собирает только
  `test_core`, новую цель стоит добавить туда же.
- Синтетический e2e (`generate.py` → `replay_ukf` → чекер → `score.py`)
  не перезапускался: без сети в песочнице нет полного дерева `tools/`.
  Правки меняют поведение статусов, поэтому таблицы `docs/metrics.md`
  и пакет `evidence/` нужно пересчитать перед защитой; цифры 0.0.6
  к исправленному ядру не относятся.
- ROS-узлы не собирались (нет `rclcpp`). Проверка на нефинитные payload
  на стороне узла не добавлена: ядро теперь fail-closed, но узел всё ещё
  кладёт `NaN` из сообщения в `last_u_`.
- `wheel_latency_s` по-прежнему только диагностика, шаг plant его не
  учитывает; `dt` в узле по-прежнему зажимается в `[5, 200]` мс, включая
  отрицательные и обратные штампы. Это осознанные ограничения, но их лучше
  называть вслух.
- Ненаблюдаемость общего масштаба (`r0` / `d̄`) и невозвратность пути после
  синхронного юза правками не снимаются и не могут быть сняты в этом контуре.
- Версия ядра в `types.hpp` намеренно не поднята в этой ветке: бамп
  `kModelVersion` и перерасчёт `docs/metrics.md` относятся к слиянию.

## Статьи документации, которые эти правки отменяют

- `docs/math.md` §6 и `docs/brief.md` §5: описание ZUPT как «`ω≈0`, `notch≈0`
  в течение `zupt_hold_s`» — теперь дополнительно требуется свежесть всех
  каналов и собственная `|v| < 0.35` м/с, а тормоз не является признаком.
- `docs/math.md` §5: «`project_pd` (Якоби, Higham-lite)» — теперь это ремонт
  с быстрым путём для корректной SPD и с ограниченной сходимостью.
- `docs/math.md` §7 и `docs/architecture.md` («Деградация»): распределение
  признаков по каналам `confidence_v` / `confidence_s` изменилось (см. §3).
- `docs/brief.md` §6: список `LOST` дополняется отклонением кадра по
  контракту входа (нефинитные управления, недопустимый `dt`).

## Связанная ветка

Ветка `audit/safety-contracts` (`92d2cd9`) содержит более раннюю
подборку падающих тестов того же класса. Она сохранена; здесь проверки
написаны независимо и дополнены восстановлением после отказа, атомарностью
шага и сохранением корректной ковариации.

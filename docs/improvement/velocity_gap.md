# Разрыв скорости ноды и сырого среднего

Дата: 2026-10-03. Фильтр не менялся. Официальный checker в Docker не запускался. Считался локальный `tools/eval/offline_checker.py` на `local/official_checker/bag` (`30618_88aea4d9`). Это тот же порт `ApproximateTimeSynchronizer` (очередь 100, допуск 0.05 с, штраф возраста 0.1), который раньше дал строку 0.023698 м/с.

Живая нода на коммите `9a954fd`, `--rate 1`, полная ручка: скорость RMSE 0.024692 м/с, максимум 0.289518 м/с, 38392 пары. Эта строка здесь не заменяется.

## Что пересчитано

| Ряд | RMSE, м/с | max, м/с | пар | bias, м/с |
|---|---|---|---|---|
| Сырое среднее тележек, штамп +0.105 с | 0.023698 | 0.289518 | 12206 | +0.003012 |
| То же среднее, сетка 0.04 с, затем +0.105 с | 0.023691 | 0.289518 | 38431 | +0.002817 |

Совместных штампов тележек 12214. Сырая разница |передняя − задняя| больше 0.3 м/с — на нуле пар. Сообщений сетки 38705.

Сетка повторяет `velocity_resample` и отбрасывание неубывающего штампа из `publish_one_velocity`. Значение на сетке — линейное сырое среднее, не скорость фильтра и не `blend_velocity`.

## Что из этого следует

Сетка 0.04 с не создаёт лишнюю 0.001 м/с. На той же синхронизации она чуть ниже несжатого среднего и почти набирает число пар ноды: 38431 против 38392. Максимум тот же, 0.289518 м/с.

Сырые тележки на общем штампе всегда внутри 0.3 м/с. Сдвиг всей сетки на 0.00…0.21 с до 0.024692 не доходит: при +0.105 с выходит 0.023691 м/с, при +0.100 с — 0.023649 м/с, при +0.080 с — 0.025078 м/с.

## Хостовый повтор публикации ноды

`replay_velocity` гоняет то же ядро и ту же публикацию скорости, что нода: водяной знак без удержания ручки, кроссфейд 0.5 с, сетка 0.04 с, штамп +0.105 с, `sigma_k0` 0.0015, k₀ из `meta.yaml`. GNSS-снимков нет. Целостность «скорость NONE» не включена. Порядок событий — порядок bag, не порядок колбэков ROS. Это не официальный checker.

На 2026-10-03: событий 50690 (передняя 12216, задняя 12225, ручка 26249), позади выхода 37, опубликовано 38703, входов без доверия к тележкам 14, кроссфейд ещё не дошёл до 1 на 25 входах.

Его не закрыть без записи `/result/velocity` из прогона ROS: там другой порядок прихода в `ApproximateTimeSynchronizer`, и там есть GNSS-снимки, которых в этом повторе нет.

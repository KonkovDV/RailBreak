# RailBreak: краткое техническое описание

Актуально для невыпущенной версии 0.0.11 в PR #5. Это резервная оценка
продольной скорости и относительного пути по управляющим командам и
колёсным скоростям, без GNSS/IMU/lidar в online UKF. Не сертифицировано
для управления движением.

## Подход

Физическая модель связывает тягу, тормоз, сопротивление, уклон и инерцию.
Ковариационный UKF объединяет prediction с живыми колёсными каналами.
SCA и адаптация R уменьшают влияние некоторых рассогласований; ZUPT,
confidence и latch описывают предусмотренные режимы деградации.
C++17 core работает без ROS; ROS 2 Humble предоставляет входы/выходы.

Физическое состояние: s, v, F_bias, масса, коэффициент тяги, шесть масштабов
радиуса и mu. Для положительных параметров применяются логарифмы, для mu —
logit с ограничениями. Ускорение — диагностика, не отдельная координата.

## Что нельзя выводить из этой архитектуры

- Ненаблюдаемость абсолютного начала s не запрещает wheel-correction
  уменьшать P_ss через корреляцию со скоростью. Это уточнение относительного
  пути, не абсолютная привязка.
- Слабая различимость массы/тяги/общего радиуса зависит от возбуждения и
  допущений модели. Нельзя обещать самокалибровку любой поездки или объявлять
  одно точное ненаблюдаемое ядро для всех нелинейных режимов.
- Канал A использует posterior-параметры UKF и не независим статистически.
- Полный пакет колёсных нулей не исключает движение на заблокированных
  колёсах. Forced ZUPT сохраняет path latch; список остановок лишь гейтит
  дисперсию массы и не является бализой.
- Априор массы — процесс Гаусса–Маркова, выполняющийся по времени фильтра,
  а не повторное измерение. Его stationary R не равно гарантированной
  дисперсии всей posterior.
- NIS вычисляется до Huber, но после data-dependent адаптации R; chi-square
  калибровку нужно проверять отдельно.
- `b_s = kappa_cut·|v|·hold` — эвристический запас, не верхний bound любого slip.

## Ограничения и следующий уровень готовности

Остаются multirate timing/freeze, ROS NaN/freshness/parameter validation,
pose/quaternion/frame/covariance, интерполяция/coverage bag-пути, time-weighted
exposure и strict-JSON export. Нужны реальные профили и записи, runtime graph
tests, независимые mismatch испытания, WCET на целевом контроллере и HIL.
Пример route_10 не заменяет обследованную карту пути. PL/HMI и зелёный CI
не устанавливают SIL/THR.

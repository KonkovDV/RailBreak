## 2. Что входит в контур сдачи

Резервный 1D-контур позиционирования:
* **Входные сигналы:** положение контроллера тяги $n\in[-1,1]$, команда торможения $b\in[0,1]$, угловые скорости колёс $\omega$ (рад/с). Это нормализованный интерфейс проекта: кодировку ручки, наличие отдельного brake-сигнала, частоты и timestamp нужно подтвердить по данным заказчика.
* **Выходные сигналы:** относительная путевая координата $s$, продольная скорость кузова $v$, ковариации, статус (`UNINITIALIZED / OK / DEGRADED / LOST`), уровень защиты $PL_s$ и признак `s_unbounded`.
* **Чистота контура:** в фильтре нет подписок на GNSS, оптический поток, лидар и ИНС (проверка: `tools/eval/no_gnss_scan.py`).
* **Топик `/tram/fix`:** проекция пути на полилинию остановок со статусом `STATUS_NO_FIX`.

## 3. Обработка rosbag2-записи Организатора

Ниже пример для совместимой rosbag2-записи, не подтверждение формата будущей
выдачи и не протокол уже выполненного прогона на данных Организатора.

```bash
# 1. Топики и типы → customer_topics.yaml (адаптер и оценщик)
python tools/eval/inspect_bag.py data/bags/run01 \
  --write-yaml tram_dr_localization/config/customer_topics.yaml

# 1b. T0 pipeline (ingest, contract, splits, identify, bench, M6/M9/M10)
python tools/hackathon/t0.py data/bags/run01 --out reports/t0 \
  --ukf standalone/build/Release/replay_ukf.exe

# 2. Опционально, оффлайн: профиль h(s) по GT/лидару. Не вход фильтра.
python tools/eval/profile_from_bag.py data/bags/run01 --out data/route_10_profile.csv

# 3. Реплей через фильтр и независимый чекер конверта
python tools/eval/run_bag.py data/bags/run01 \
  --ukf standalone/build/replay_ukf \
  --route tram_dr_localization/config/route_10.yaml \
  --vehicle tram_dr_localization/config/vehicle_lvenok_moscow.yaml \
  --baselines
```

## 5. Состояние решения к сдаче

Ядро `tramDR-0.0.11` находится на `main`. История изменений —
[`CHANGELOG.md`](CHANGELOG.md); граница проверенного —
[`docs/verification.md`](docs/verification.md).
Мы не утверждаем «ошибок нет» или «всё кодом закрыто».

**Открыты и технические проверки:** freeze/multirate, ROS runtime graph,
bag interpolation/coverage, полный domain генератора, malformed input и
воспроизводимость evidence. Часть можно проверить в репозитории до получения
реального bag. Приоритеты и условия закрытия —
[OSINT/triage](docs/review/osint-triage.md).
Внешние зависимости — отдельно:

| Пункт | Суть | Почему не закрыт к сдаче |
| --- | --- | --- |
| пп. 14.4–14.6 | согласование публикации/прав | наличие письма в NOTICE не означает его отправку или согласие |
| bag организатора | реальные записи и контракт сигналов | слот [`data/bags/`](data/bags/README.md); формат и доступность подтвердить по ТЗ |
| действующее Положение | текст требований и нумерация | публичная ссылка найдена; текст PDF в этой OSINT-порции не извлечён |

Исторические статусы отдельных находок в CHANGELOG не заменяют текущую
матрицу испытаний и не означают готовность всей системы к эксплуатации.

Худший межостановочный перегон маршрута 10 в YAML — **Бурназяна** ($s=408.4$ м)
→ **Исаковского, 33** ($s=2794$ м): $2385.6$ м. В необслуживаемом режиме
(процессный шум без колёс, $v=16.7$ м/с, $q_v=0.0025$ м²/с³):
$\sigma_s=49.29$ м, $PL_s=124.05$ м, $AL_s=124.28$ м. Запас по уровню —
**0.23 м (0.18 % от $AL$)**. $PL=AL$ на $2393.9$ м: запас по длине —
**8.3 м (0.35 % перегона)**. Это совпадение параметров, не проектный зазор;
к этому моменту статус уже `LOST` по `age_lost_s`. В номинале 1 % по диаметру
даёт 23.9 м на том же перегоне. Это q-only иллюстрация, не полный safety bound.

Чего в репозитории нет и что не заявляется: сертификация SIL/CENELEC, прогон на
записи Организатора, полевая калибровка $r_0$ и $m_0$ по bag. Оценки геометрии
Строгинского моста (уклон 25–40 ‰) — OSINT для генератора сценариев, а не данные
изысканий и не вход фильтра.
